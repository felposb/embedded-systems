O que é comunicação de dados

Em uma fraseComunicação de dados é a troca de informação entre dispositivos eletrônicos por um canal, seguindo regras combinadas: o protocolo.

Desde as pinturas nas cavernas até o Wi-Fi, isso nunca mudou: alguém transmite, alguém recebe, existe uma mensagem, existe um meio para levá-la, e ela precisa ser compreendida. Com máquinas, a mensagem vira bits.

Dado

“23”

O valor bruto, sem contexto.

Informação

“23 °C na estufa”

O dado interpretado, com contexto.

Sinal

tensão, luz, rádio

A forma física que carrega os bits pelo canal.

Ruído

Qualquer interferência que distorce, atrasa ou apaga parte da mensagem. Exemplos: motor perto do cabo, cabo danificado, parede entre roteador e celular, sinal fraco, rede congestionada.

Protocolo

As regras da conversa: formato, velocidade, ordem dos bytes, o que cada byte significa. Frase dos labs: “Dois fios não fazem uma conversa. Um protocolo, sim.”

Claude Shannon, 1948

Shannon transformou informação em algo que se mede (o bit). Uma mensagem previsível carrega pouca informação; uma inesperada carrega muita. Para a engenharia, o que importa não é o significado, e sim como codificar, transmitir e recuperar a mensagem com segurança, mesmo com ruído.

Comunicação serial × paralela

Em uma fraseNa paralela, vários bits viajam ao mesmo tempo, cada um no seu fio. Na serial, os bits viajam em fila, um depois do outro, no mesmo fio.

O mesmo byte 10110010, agora em fila. Menos fios, mais barato, alcança mais longe.

Pense assim

Paralela = 8 carros lado a lado numa estrada de 8 faixas: chegam juntos, desde que nenhum atrase. Serial = fila indiana numa estrada de uma faixa: um de cada vez, mas a estrada é barata e dá para correr muito.

Pegadinha

“Paralela é sempre mais rápida” está errado na prática. Em cabos longos e rápidos os bits deixam de chegar juntos. Por isso quase tudo o que sai de uma placa hoje é serial.

Comunicação síncrona × assíncrona

Em uma fraseSíncrona tem um fio de clock dizendo “leia agora”. Assíncrona não tem clock: os dois lados combinam a velocidade antes e usam start/stop para se encontrar no tempo.

Síncrona

  • Existe clock no barramento
  • A borda do clock marca o instante de leitura
  • O receptor não precisa “adivinhar” o tempo
  • Exemplos: I²C (SCL), SPI (SCK)

Assíncrona

  • Sem fio de clock
  • Os dois lados combinam o baud rate (ex.: 9600)
  • Start bit (0) e stop bit (1) enquadram cada byte
  • Exemplo: UART

Síncrona: a cada subida do clock (linha de cima), o receptor lê o valor da linha de dados (linha de baixo).

Pense assim

Síncrona = uma banda com baterista: todo mundo toca na batida dele. Assíncrona = duas pessoas com relógios acertados que combinaram “falo uma sílaba por segundo”, e antes de cada palavra alguém diz “atenção!” (start bit).

Pegadinha

Síncrono não quer dizer “os dois falam ao mesmo tempo”. Síncrono/assíncrono é sobre clock (quando ler). Simplex/half/full é sobre sentido (quem fala quando). O I²C é síncrono e half-duplex; a UART é assíncrona e full-duplex.

Como descobrir na prova

Conte os caminhos de dados. Um fio de dados compartilhado pelos dois lados → half. Um fio para cada sentido → full. Só existe transmissor de um lado → simplex.

Topologias de comunicação

Em uma fraseTopologia é o desenho de quem se liga a quem. Ela define quantos fios, o que acontece quando algo quebra e como escolher quem fala.

Ponto a ponto

Dois dispositivos, ligação exclusiva. Simples, sem endereço. Ex.: UART, RS-232.

Barramento (multiponto)

Todos no mesmo meio. Poucos fios, mas precisa de endereço ou seleção. Ex.: I²C, RS-485.

Estrela

Todos ligados a um centro. Fácil de gerenciar, mas se o centro cai, cai tudo. Ex.: roteador Wi-Fi.

Anel

Cada nó passa a mensagem ao vizinho, em roda. Um nó quebrado pode interromper o anel (há anéis com redundância na indústria).

Malha (mesh)

Nós repassam mensagens uns dos outros; há caminhos alternativos se um cair. Ex.: Zigbee, Thread.

Estrela de estrelas

Sensores → vários gateways → um servidor central. Ex.: LoRaWAN.

Pegadinha

Barramento compartilhado exige uma forma de escolher quem fala: endereço (I²C, Modbus) ou pino de seleção (SPI, com CS). Ponto a ponto não precisa disso.

GPIO: os pinos faz-tudo

Em uma fraseGPIO (General Purpose Input/Output) são pinos que você configura como entrada (ler um botão) ou saída (acender um LED). É a comunicação mais simples: um bit por pino, alto ou baixo.

Pense assim

Como saída, o pino é um interruptor que o Arduino liga e desliga. Como entrada, é um olho que olha se um interruptor lá fora está ligado.

FunçãoO que faz
pinMode(8, OUTPUT)Pino vira saída
pinMode(2, INPUT)Entrada “pura”: precisa de resistor externo, senão fica flutuando
pinMode(2, INPUT_PULLUP)Entrada com resistor interno ligado ao 5 V. Solto = HIGH, pressionado = LOW
digitalWrite(8, HIGH)Coloca 5 V (ou 3,3 V) no pino
digitalRead(2)Devolve HIGH ou LOW
analogRead(A0)Lê tensão analógica: 0 a 1023 (ADC de 10 bits no UNO)
analogWrite(9, 128)PWM de 0 a 255 (liga-desliga rápido; não é tensão analógica de verdade)
pinMode(2, INPUT_PULLUP);        // resistor interno puxa o pino para 5 V
// botão ligado entre o pino 2 e o GND
if (digitalRead(2) == LOW) {     // LOW = botão PRESSIONADO
  digitalWrite(8, HIGH);
}
Pegadinha: pino flutuando

Entrada sem pull-up nem pull-down lê valores aleatórios (capta ruído). Solução: INPUT_PULLUP com botão para o GND, ou resistor externo.

Pegadinha: lógica invertida

Com INPUT_PULLUP, pressionado é LOW. Código que testa == HIGH fica ao contrário.

Detectar o aperto (borda), não o nível

O loop() roda milhares de vezes por segundo. Se o código só olhar “está pressionado?”, ele envia o comando centenas de vezes. O gabarito dos labs guarda o estado anterior:

static bool last = HIGH;
bool b = digitalRead(BUTTON);
if (last == HIGH && b == LOW) Serial.write(0x01); // só no instante do aperto
last = b;

Piscar sem travar: millis() no lugar de delay()

unsigned long agora = millis();
if (agora - anterior >= periodo) {  // passou o tempo?
  anterior = agora;
  estado = !estado;
  digitalWrite(LED, estado);
}
// o loop continua livre para ler a Serial

delay(1000) congela o programa inteiro por 1 segundo: nada é lido nesse tempo.

UART: duas placas, dois fios de conversa

Em uma fraseA UART transforma cada byte numa fila de bits e envia pelo TX, recebendo pelo RX. Não tem clock: os dois lados combinam a velocidade (baud rate) e o formato do quadro.

Pense assim

Duas casas vizinhas com um fio esticado. Cada byte vai num “envelope”: começa com um sinal de atenção (start bit = 0), leva 8 bits de dados e termina com um “câmbio” (stop bit = 1). Os dois combinaram antes a velocidade de fala.

  • Fios mínimos: TX, RX e GND. Normalmente é ponto a ponto.
  • Full-duplex: TX e RX são linhas independentes.
  • Assíncrona: baud rate igual nos dois lados (9600, 19200, 38400, 57600, 115200).
Simulador · quadro UART

Contas que caem

Tbit = 1 / baud. Em 9600: 104,17 µs por bit. Quadro 8N1 = 10 bits → 1,04 ms por byte → 960 bytes/s úteis (7680 bits úteis/s). Em 115200: 11 520 bytes/s.

As funções da Serial

FunçãoO que faz
Serial.begin(9600)Configura a velocidade (padrão 8N1). Os dois lados precisam bater.
Serial.print(x) / println(x)Envia texto. println acrescenta \r\n. println(255, HEX) → “FF”.
Serial.write(b) / write(buf, n)Envia bytes crus. write(65) manda 1 byte (o ‘A’). Retorna quantos bytes enfileirou.
Serial.available()Quantos bytes estão esperando no buffer. Só consulta, não tira nada.
Serial.read()Tira 1 byte do buffer (0 a 255). Retorna -1 se estiver vazio (por isso devolve int).
Serial.readBytes(buf, n)Lê vários bytes para um vetor; pode esperar até o timeout; retorna quantos leu.
Serial.readStringUntil('\n')Lê texto até o caractere. Use trim() para tirar o \r que sobra.

Protocolo próprio sobre a UART

A UART só transporta bytes. O que cada byte significa é você quem define. Exemplo da aula, pacote de 3 bytes:

// Arduino A - Transmissor
// [INICIO] [COMANDO] [VALOR]
byte pacote[] = {0xAA, 0x01, 0x01};      // LED ON
Serial.write(pacote, sizeof(pacote));

// Arduino B - Receptor
if (Serial.available() >= 3) {          // espera o pacote inteiro
  byte inicio  = Serial.read();
  byte comando = Serial.read();
  byte valor   = Serial.read();
  if (inicio == 0xAA && comando == 0x01) {
    digitalWrite(10, valor == 0x01 ? HIGH : LOW);
  }
}

Protocolo do gabarito da Questão 4 (primeiro byte = qual comando):

ByteSignificadoDados extras
0x01Ligar LED remotonenhum
0x02Consultar estado do LEDnenhum
0x03Configurar período do pisca1 byte (0 a 15 do DIP switch)
0x80 / 0x81Resposta: LED desligado / ligadonenhum

Valor de 16 bits não cabe num quadro (8 bits de dados): divide em dois com highByte() e lowByte(), e remonta com word(alto, baixo).

Buffer cheio

TX cheio: você escreve mais rápido que a UART transmite, e write passa a bloquear (loop lento). RX cheio: bytes chegam mais rápido do que o loop lê, e bytes novos se perdem (comando truncado). Conta: 115200 8N1 ≈ 11 520 B/s. Mandar 50 bytes a cada 1 ms = 50 000 B/s → não cabe.

Pegadinhas de UART
  • TX com TX não funciona: é TX → RX cruzado, mais GND comum.
  • Baud diferente dos dois lados → caracteres “malucos”.
  • Serial.read() sem checar available() → lê -1, que guardado em byte vira 255 (0xFF).
  • Entre dois Arduinos, o lab exige write/read (bytes), não print/println (texto).
  • readStringUntil('\n') deixa o \r: “LED ON\r” ≠ “LED ON”. Faça msg.trim().

I²C: um corredor, vários dispositivos

Em uma fraseI²C é um barramento síncrono de 2 fios (SDA dados + SCL clock) em que um mestre conversa com vários dispositivos chamando cada um pelo seu endereço de 7 bits.

Pense assim

Sala de aula: o professor (mestre) faz a chamada pelo número (endereço). Todo mundo ouve, mas só quem tem aquele número responde “presente!” (ACK). E só o professor começa a conversa.

  • Fios: SDA, SCL e GND comum. No UNO/Nano: SDA = A4, SCL = A5.
  • Pull-ups obrigatórios: os dispositivos só puxam a linha para 0; o resistor devolve para 1.
  • Half-duplex: uma única linha de dados, usada em um sentido de cada vez.
  • Endereço de 7 bits: até 128 combinações (algumas reservadas). Dois módulos com o mesmo endereço = conflito → jumpers A0/A1/A2, outro endereço por software ou multiplexador.
  • Velocidades: Standard 100 kHz · Fast 400 kHz · Fast Plus 1 MHz · High Speed 3,4 MHz. Wire.setClock(400000).
  • Regra do clock: SDA só muda com SCL baixo e é lido com SCL alto. Exceção: START (SDA desce com SCL alto) e STOP (SDA sobe com SCL alto).
Simulador · byte de endereço
Operação

Passo a passo · mestre lê 2 bytes do registrador TEMP (0x00) do sensor 0x48

// ===== ESCRAVO (endereço 0x08) =====
volatile byte regPedido = 0;

void receiveEvent(int n) {            // mestre ESCREVEU
  byte reg = Wire.read();             // 1º byte = registrador
  regPedido = reg;
  if (reg == 0x00 && Wire.available()) {
    digitalWrite(8, Wire.read());     // 2º byte = valor do LED
  }
}
void requestEvent() {                 // mestre PEDIU dados
  if (regPedido == 0x01) {
    Wire.write(lowByte(temp_x10));    // baixo primeiro
    Wire.write(highByte(temp_x10));   // depois o alto
  }
}
void setup() {
  Wire.begin(0x08);                   // vira escravo
  Wire.onReceive(receiveEvent);
  Wire.onRequest(requestEvent);
}

// ===== MESTRE =====
uint16_t read16(byte reg) {
  Wire.beginTransmission(0x08);
  Wire.write(reg);                    // escolhe o registrador
  Wire.endTransmission(false);        // sem STOP (repeated start)
  Wire.requestFrom(0x08, (byte)2);    // pede 2 bytes
  if (Wire.available() >= 2) {
    byte lo = Wire.read();            // mesma ordem do escravo!
    byte hi = Wire.read();
    return ((uint16_t)hi << 8) | lo;  // junta os dois bytes
  }
  return 0;
}
Pegadinhas de I²C
  • Escravo com Wire.begin() sem endereço não aparece no scanner.
  • Esquecer Wire.onRequest(...) → o mestre pede e não recebe nada útil (0xFF).
  • Ordem dos bytes trocada: 253 (0x00FD) vira 0xFD00 = −768 → “−76,8 °C”.
  • O significado dos bytes (registrador, valor) é do seu protocolo, não do I²C.
  • Em requestFrom(addr, 2), o “2” não é enviado ao escravo: é o mestre que decide quantos bytes lê.
  • Scanner: endTransmission() == 0 significa que alguém deu ACK naquele endereço.
Roteiro de bancada

1) Ligue GND, SDA, SCL e confira pull-ups. 2) Rode o scanner e confirme o endereço. 3) Grave o escravo e abra o Serial do mestre. 4) Mude valores no escravo e veja a leitura mudar. Scanner não acha nada? GND comum, fios invertidos, alimentação.

SPI: rápido, com um fio de seleção para cada

Em uma fraseSPI é um barramento síncrono e full-duplex de 4 fios. Não usa endereço: o controlador escolhe o periférico colocando o pino CS dele em LOW.

Pense assim

O professor tem um cordão amarrado em cada aluno. Ele puxa o cordão (CS em LOW) de quem deve falar. É mais rápido que fazer chamada, mas precisa de um cordão para cada aluno.

LinhaNomeFunçãoUNO
SCKSerial ClockPulsos que sincronizam cada bit13
MOSIMaster Out Slave InDados do controlador para o periférico11
MISOMaster In Slave OutDados do periférico para o controlador12
CS/SSChip/Slave SelectSeleciona o periférico. Ativo em LOW10

Full-duplex: 8 pulsos de clock = 1 byte sai pelo MOSI e 1 byte entra pelo MISO, ao mesmo tempo. Por isso SPI.transfer(x) devolve um byte.

#include <SPI.h>
const byte CS = 10;
void setup() {
  SPI.begin();
  pinMode(CS, OUTPUT);
  digitalWrite(CS, HIGH);              // ninguém selecionado
}
byte conversa(byte comando) {
  digitalWrite(CS, LOW);               // "é com você"
  SPI.beginTransaction(SPISettings(1000000, MSBFIRST, SPI_MODE0));
  byte resposta = SPI.transfer(comando); // envia e recebe junto
  SPI.endTransaction();
  digitalWrite(CS, HIGH);              // "terminei"
  return resposta;
}
Pegadinhas de SPI
  • CS esquecido em HIGH → o periférico ignora tudo.
  • Dois CS em LOW ao mesmo tempo → os dois respondem no MISO e os dados colidem.
  • 3 periféricos = SCK + MOSI + MISO + 3 CS = 6 fios de sinal.
  • A biblioteca SPI do Arduino é feita para o Arduino ser o controlador.

Resumo da aula

SPI prioriza velocidade e protocolo simples. I²C prioriza economia de fios e vários dispositivos. UART é a conversa direta entre dois. Critérios: fios/pinos disponíveis, velocidade, quantos dispositivos, distância e ruído, e o que o dispositivo suporta.

Uma carta: o Modbus é o formulário padronizado (“Para: dispositivo 2. Pedido: ler registrador 100”). A UART é a forma de escrever letra por letra. O RS-485 é o caminhão blindado que leva a carta por estradas cheias de buraco (ruído).

TTL: o nível lógico da própria placa

Em uma fraseTTL (ou CMOS) é o sinal direto do microcontrolador: 0 V é 0, e 5 V (ou 3,3 V) é 1. Funciona bem em distâncias curtas, dentro da placa ou entre placas vizinhas.

  • É o que sai do TX/RX do Arduino, do SDA/SCL, do SPI.
  • Sem proteção contra ruído e sem alcance: cabo longo ou motor perto → erros.
  • 5 V ≠ 3,3 V: o TX de um Arduino UNO (5 V) pode danificar a entrada de uma ESP32 (3,3 V). Use conversor de nível ou divisor de tensão.

RS-232: ponto a ponto, com tensões próprias

Em uma fraseRS-232 é uma interface elétrica ponto a ponto, clássica das portas seriais de computador, que usa tensões positivas e negativas e lógica invertida.

Características

  • Níveis de ±3 V a ±15 V
  • Lógica invertida: 1 = tensão negativa, 0 = positiva
  • Ponto a ponto (2 dispositivos)
  • Distância curta: cerca de 15 m
  • TX, RX, GND (full-duplex); conector DB9

Na prática

Microcontrolador (UART TTL) → MAX232 (conversor de nível) → cabo RS-232 → outro equipamento.

Nunca ligue uma UART de 5 V/3,3 V direto numa porta RS-232.

Uso típico: computador ↔ instrumento, equipamentos antigos, alguns CLPs.

RS-485: diferencial, longe e com vários

Em uma fraseRS-485 manda cada bit pela diferença de tensão entre dois fios (A e B). O ruído atinge os dois fios igualmente e se cancela, por isso vai longe e aguenta ambiente industrial.

Simulador · ruído no fio comum × no par diferencial

TTL (um fio + GND)

Enviando bit 0 = 0 V. Acima de ~2 V o receptor lê 1.

RS-485 (A e B)

Enviando bit 1: A = 3,5 V, B = 1,5 V. O receptor olha A − B.

Números

  • Alcance: até ~1200 m
  • Até 32 dispositivos (cargas padrão)
  • Multiponto (barramento)
  • 2 fios = half-duplex (4 fios permite full)
  • Terminação de ~120 Ω nas duas pontas evita reflexões

Transceiver (ex.: MAX485)

Converte UART TTL ↔ A/B. Em 2 fios, só um fala por vez: o pino DE/RE escolhe transmitir (HIGH) ou receber (LOW).

digitalWrite(DE_RE, HIGH);   // liga o transmissor
Serial.write(quadro, n);
Serial.flush();              // espera o último bit sair
digitalWrite(DE_RE, LOW);    // volta a escutar a resposta
Pense assim

Duas pessoas no mesmo elevador. Se o elevador sobe 3 andares (ruído), as duas sobem juntas, mas a diferença de altura entre elas continua a mesma. O RS-485 só olha essa diferença.

Modbus: agora é a mensagem

Em uma fraseModbus é um protocolo aberto (Modicon, 1979) de mestre e escravos: o mestre pergunta, o escravo endereçado responde. Ele define formato, endereço, função e dados, mas não o cabo.

  • Muito usado em CLPs, sensores, inversores, medidores.
  • Roda sobre RS-232, RS-485 (Modbus RTU) ou Ethernet (Modbus TCP, porta 502).
  • Só o mestre inicia. Escravos só respondem, o que evita colisão no barramento half-duplex.

Bluetooth Low Energy (BLE)

Em uma fraseBLE é o Bluetooth feito para gastar pouquíssima energia trocando pequenos dados. O dispositivo se anuncia, o celular conecta e então lê ou escreve valores organizados em serviços e características.

  • Bluetooth nasceu nos anos 1990 para substituir cabos. Faixa ISM de 2,4 GHz, não licenciada. Forma PANs (redes pessoais). Mantido pelo Bluetooth SIG.
  • Classic (BR/EDR): comunicação contínua, áudio, consumo maior.
  • BLE: criado no Bluetooth 4.0 (2010). Advertising para descoberta, conexão para dados, GATT, consumo muito baixo.

Pegadinha

Properties (READ, WRITE, NOTIFY) dizem o que a Characteristic sabe fazer. O CCCD (0x2902) é o Descriptor onde cada cliente liga o Notify. A Characteristic do LED (READ | WRITE) não precisa de CCCD; a de Temperatura com NOTIFY precisa.

O exemplo da aula: ligar um LED pelo celular (ESP32)

Em uma fraseO celular não mexe no GPIO: ele escreve “1” ou “0” numa Characteristic, e o código do ESP32 transforma esse valor em digitalWrite.

#include <BLEDevice.h>   // inicializa o BLE
#include <BLEServer.h>   // cria GATT Server, Services, Characteristics
#include <BLEUtils.h>
#define LED_PIN 17
#define SERVICE_UUID            "12345678-1234-1234-1234-1234567890AB"
#define LED_CHARACTERISTIC_UUID "12345678-1234-1234-1234-1234567890AC"

class LedCallbacks : public BLECharacteristicCallbacks {
  void onWrite(BLECharacteristic *pCharacteristic) override { // celular fez WRITE
    String valor = pCharacteristic->getValue();   // -> porque é ponteiro
    if (valor == "1") {
      digitalWrite(LED_PIN, HIGH);
      pCharacteristic->setValue("1");             // próximo READ devolve "1"
    } else if (valor == "0") {
      digitalWrite(LED_PIN, LOW);
      pCharacteristic->setValue("0");
    }                                             // outro valor: ignorado
  }
};

class ServerCallbacks : public BLEServerCallbacks {
  void onConnect(BLEServer *pServer) override { Serial.println("Celular conectado!"); }
  void onDisconnect(BLEServer *pServer) override {
    Serial.println("Celular desconectado!");
    BLEDevice::startAdvertising();                // volta a aparecer no scan
  }
};

void setup() {
  Serial.begin(115200);
  pinMode(LED_PIN, OUTPUT);
  digitalWrite(LED_PIN, LOW);

  BLEDevice::init("ESP32_LED_BLE");               // nome visto no nRF Connect
  BLEServer *pServer = BLEDevice::createServer(); // GATT Server
  pServer->setCallbacks(new ServerCallbacks());
  BLEService *pService = pServer->createService(SERVICE_UUID);

  BLECharacteristic *pLed = pService->createCharacteristic(
    LED_CHARACTERISTIC_UUID,
    BLECharacteristic::PROPERTY_READ | BLECharacteristic::PROPERTY_WRITE);
  pLed->setValue("0");                            // estado inicial
  pLed->setCallbacks(new LedCallbacks());         // sem isto, onWrite nunca roda

  pService->start();                              // ativa o Service
  BLEAdvertising *pAdv = BLEDevice::getAdvertising();
  pAdv->addServiceUUID(SERVICE_UUID);
  pAdv->setScanResponse(true);
  BLEDevice::startAdvertising();                  // começa a anunciar
}
void loop() { delay(1000); }
O que dá errado se faltar…
  • PROPERTY_WRITE → celular só consegue ler.
  • setCallbacks(new LedCallbacks()) → valor é salvo, mas o LED não reage.
  • startAdvertising() no onDisconnect → depois de desconectar, o ESP32 some do scan.
  • pService->start() → o Service não fica disponível.
  • Celular manda “ON” mas o código compara com “1” → ignorado. O formato do dado é combinado dos dois lados.

Exercício da aula: ler o potenciômetro criando outra Characteristic com PROPERTY_READ e, no onRead, fazer c->setValue(String(analogRead(POT_PIN)).c_str()).

Zigbee (e Thread)

Em uma fraseZigbee é uma rede de baixo consumo em malha: cada aparelho ligado na tomada repassa mensagens dos outros, cobrindo a casa inteira.

  • Rádio IEEE 802.15.4, 2,4 GHz, ~250 kbps.
  • Papéis: coordenador (cria a rede), roteadores (repassam), dispositivos finais (sensores a bateria que dormem).
  • Alcance por salto de ~10–100 m, mas a malha estende a cobertura.
  • Thread: mesmo rádio 802.15.4, malha com IPv6; base do Matter.
Pense assim

Um recado passado de vizinho em vizinho até chegar ao destino. Se um vizinho viajou, o recado dá a volta por outra rua.

LoRa e LoRaWAN

Em uma fraseLoRa fala devagar, mas é ouvida a quilômetros e gasta tão pouca energia que um sensor dura anos com pilha.

  • LoRa é a modulação de rádio (espalhamento por chirp), em faixa sub-GHz (915 MHz no Brasil).
  • LoRaWAN é o protocolo de rede por cima: dispositivos → gateways → servidor de rede (estrela de estrelas).
  • Alcance de km (2–5 km em cidade, 15 km ou mais no campo). Taxa de centenas de bit/s a dezenas de kbit/s.
  • Perfeito para pacotes pequenos e esporádicos; inútil para áudio ou vídeo.
Pense assim

Alguém falando bem devagar e pausado num vale: a voz vai longe e é entendida, mas você não conseguiria contar um filme assim.

Vetor: caixinhas em fila na memória

Em uma fraseUm vetor é um bloco contínuo de memória com vários elementos do mesmo tipo, acessados por índice que começa em 0.

int notas[5] = {8, 7, 9, 6, 10};
printf("%d\n", notas[0]);   // 8  (o primeiro é o índice 0)
printf("%d\n", notas[2]);   // 9
printf("%d\n", notas[5]);   // LIXO: fora do vetor! C não confere limites
TipoPC (aula de C)Arduino UNO (labs)
char / byte1 byte1 byte (byte = 0 a 255)

long4 ou 8 bytes4 bytes
float4 bytes4 bytes
double8 bytes4 bytes

sizeof(vetor) = tamanho do tipo × quantidade. int v[4]: 16 bytes no PC, 8 no UNO. sizeof(v[0]) = tamanho de um elemento.

String é vetor de char terminado em \0

char nome[6] = "Javan";      // J a v a n \0  (5 letras + terminador)
printf("%s\n", nome);        // Javan  (%s imprime até o \0)
printf("%c\n", nome[0]);     // J      (%c imprime um caractere)
printf("%d\n", nome[5]);     // 0      (o terminador vale 0)

char c = 'A';
printf("%d\n", c);           // 65  (código ASCII)
printf("%c\n", c + 32);      // a   (maiúscula + 32 = minúscula)
'A''Z''a''z''0''9'espaço
659097122485732

Ligação com comunicação: o computador não guarda letras, guarda códigos. Mapear símbolo → número é codificar; é isso que permite transmitir e depois decodificar.

Ponteiro: o endereço, não a casa

Em uma fraseUm ponteiro é uma variável que guarda um endereço de memória: não o valor, mas onde o valor está.

Pense assim

A variável é a casa, com alguém morando dentro (o valor). O ponteiro é um papel com o endereço da casa escrito. Com o papel você chega na casa e pode trocar quem mora lá.

int x = 10;
int *p = &x;      // p guarda o ENDEREÇO de x   (& = "endereço de")
printf("%d\n", *p); // 10                      (* = "conteúdo apontado por")
*p = 25;           // muda o conteúdo no endereço → agora x vale 25
printf("%p\n", (void*)p);  // imprime o endereço (use %p, não %d)

x

O conteúdo: 10

&x

O endereço de x: 0x100

*p

O valor que está no endereço guardado em p: 10

Mesmo símbolo, papéis diferentes

Na declaração (int *p), o * cria um ponteiro. Numa expressão (*p = 25), o * acessa o valor apontado. O tipo do ponteiro diz quantos bytes ler e como interpretar.

Ponteiro e vetor

O nome do vetor já é o endereço do primeiro elemento: int *p = v;. Então *p == v[0], *(p+1) == v[1]. p + 1 avança um elemento, não um byte.

Simulador de memória

int historico[5] = {20, 25, 27, 31, 35};
Plataforma
Tipo do ponteiro

Os bytes aparecem em hexadecimal. O Arduino e o PC guardam o byte menos significativo primeiro (little-endian): 20 = 0x0014 vira 14 00.

Passagem por valor × por endereço

Por valor: recebe uma cópia

void dobrar(int n) {
  n = n * 2;       // muda só a cópia
}
int x = 5;
dobrar(x);
printf("%d", x);   // 5

Por endereço: mexe no original

void dobrar(int *n) {
  *n = *n * 2;     // muda o original
}
int x = 5;
dobrar(&x);
printf("%d", x);   // 10
Erros comuns
  • Ponteiro não inicializado: int *p; *p = 5; escreve num endereço qualquer. Inicialize com um endereço válido ou NULL e teste.
  • Esquecer o &: scanf("%d", idade) em vez de &idade.
  • %d para ponteiro: use %p com (void*).
  • sizeof dentro da função: vetor recebido como parâmetro vira ponteiro; sizeof dá o tamanho do ponteiro. Por isso o tamanho vai como parâmetro.

Onde isso aparece no Arduino

  • Serial.write(pacote, sizeof(pacote)) e Serial.readBytes(buf, 4): passam o endereço do vetor.
  • Wire.write(buf, len): mesmo padrão no I²C.
  • pCharacteristic->getValue(): -> acessa um membro através de um ponteiro (igual a (*p).getValue()).
  • ((uint16_t)hi << 8) | lo: junta dois bytes num valor de 16 bits.

O bug do Lab 1, resolvido

Enunciado: histórico das últimas 5 leituras, valor limitado entre 0 e 100. Com historico = {20, 25, 27, 31, 35} e temperatura = 125, o resultado certo é 25, 27, 31, 35, 100.

// CÓDIGO COM PROBLEMAS
void limitarTemperatura(int temperatura) {        // (1) recebe CÓPIA
  if (temperatura < 0)   temperatura = 0;
  if (temperatura > 100) temperatura = 100;      //     muda só a cópia
}
void registrarLeitura(byte *vetor, int tamanho, int nova) { // (2) byte* num vetor de int
  for (int i = 0; i < tamanho - 1; i++)
    *(vetor + i) = *(vetor + i + 1);               //     anda 1 BYTE por vez
  *(vetor + tamanho - 1) = nova;
}
limitarTemperatura(temperatura);
registrarLeitura((byte *)historico, 5, temperatura);
Problema 1

Passagem por valor: temperatura continua 125. Correção: devolver o valor (return) ou receber ponteiro.

Problema 2

No UNO cada int tem 2 bytes. Com byte*, a função desloca bytes soltos (só metade do vetor) e grava 125 num byte. Correção: int *vetor e tirar o cast.

// CORRIGIDO
int limitarTemperatura(int t) {
  if (t < 0)   t = 0;
  if (t > 100) t = 100;
  return t;
}
void registrarLeitura(int *vetor, int tamanho, int nova) {
  for (int i = 0; i < tamanho - 1; i++)
    *(vetor + i) = *(vetor + i + 1);   // desloca para a esquerda
  *(vetor + tamanho - 1) = nova;       // nova leitura no fim
}
temperatura = limitarTemperatura(temperatura);   // 100
registrarLeitura(historico, 5, temperatura);     // 25, 27, 31, 35, 100
